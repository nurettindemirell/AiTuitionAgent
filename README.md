AI Tuition Agent

This project is an AI agent–based chat application developed for the SE4458 course assignment.
It builds on the APIs implemented in the Midterm and allows students to handle tuition-related tasks simply by chatting with the system in natural language.

With this application, students can:

Check their tuition fees

Pay their tuition

View a list of unpaid tuition fees

Project Overview

The system is designed as a conversational, AI-powered interface.
Instead of navigating forms or calling APIs manually, users just type what they want, and the system takes care of the rest.

Behind the scenes, the application:

Understands what the user wants (intent detection) using an LLM

Extracts the necessary details such as student number, term, and amount

Forwards the request through an API Gateway

Calls the appropriate Midterm API

Sends a clear response back to the chat interface

Architecture and Design

The project follows the API Gateway Pattern and is divided into two main parts:

Frontend (React)

Provides a simple chat-based user interface

Sends user messages to the backend gateway

Displays the responses generated by the AI agent

Never communicates directly with the Midterm APIs—all requests go through the gateway

Backend (Node.js / Express)

Acts as the central API Gateway

Receives messages from the frontend

Uses OpenAI (gpt-4o-mini) to:

Understand the user’s intent

QUERY_TUITION, PAY_TUITION, UNPAID_TUITION

Extract required parameters

studentNo, term, amount

Calls the relevant Midterm APIs based on the detected intent

Returns the final result to the frontend

Overall Flow
User → React Chat UI → Node.js Gateway
     → OpenAI (intent & parameter extraction)
     → Midterm APIs
     → Gateway → React UI

AI Agent Behavior

The AI agent focuses on making the interaction feel natural and flexible.
It can understand casual user messages, map them to the correct action, and pull structured data from free-text input.

Example interactions:

“check my tuition” → QUERY_TUITION

“pay tuition for fall 2026 15000” → PAY_TUITION

“show unpaid tuition for spring 2026” → UNPAID_TUITION

If the user leaves out required information, the system smoothly continues the conversation by asking for what’s missing, such as:

Student number

Term (FALL / SPRING / SUMMER)

Payment amount

APIs Used

All requests are routed through the gateway to keep the system clean and consistent:

Tuition Inquiry
GET /api/v1/banking/tuition

Tuition Payment
POST /api/v1/banking/pay

Unpaid Tuition List
GET /api/v1/admin/tuition/unpaid

For simplicity and to meet assignment requirements, authentication is handled using a fixed username and password.

Assumptions

A fixed admin account is used for authentication

Student numbers are numeric

Academic terms follow the format FALL-YYYY, SPRING-YYYY, or SUMMER-YYYY

Challenges Faced

During development, several practical challenges came up:

Managing multi-step conversations when the user provides incomplete information

Distinguishing between a term year (e.g., 2026) and a payment amount in user messages

Keeping the frontend and backend in sync in a chat-based flow

Ensuring that all API calls strictly pass through the gateway

Dealing with token context limits and AI usage costs

How to Run the Project
Backend
cd backend
npm install
node index.js

Frontend
cd frontend
npm install
npm start


The backend runs on http://localhost:3001, and the frontend communicates with it via the /gateway endpoint.

Conclusion

This project shows how traditional REST APIs can be turned into a conversational experience using an AI agent.
By combining LLM-based intent and parameter extraction with an API Gateway architecture, the SE4458 assignment requirements are fully met while providing a more user-friendly interaction model.
